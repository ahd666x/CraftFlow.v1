# CNC reverse-engineering engine — stages 2–7

## Implemented

1. **Diagnostics baseline:** see `reports/sample_diagnostics.json`. It is for the repository fixture `sample.cnc`, not the separately referenced `t.16.1090x450.2set.cnc`, which was not supplied.
2. **Parser and IR:** `engine/parser.py` builds a typed, source-line-linked IR for modal G0–G3 motion, absolute/incremental coordinates, G20/G21 units, G17/G18/G19 planes, G53 machine-frame moves, tool/feed/spindle/H-register metadata, source-block IDs and observed G/M commands. Inch coordinates are normalized to millimetres; undeclared units remain unspecified. Unknown commands, macro expressions, control flow and compact controller tokens are preserved as warnings, not silently expanded or interpreted. An implicit G17 is used only as a flagged read-only geometry assumption.
3. **Geometry model:** `engine/geometry.py` reconstructs blocks, connectivity, depth and projected bounds; valid IJK arcs get analytic projected extrema in XY/XZ/YZ planes. R-format arcs, incomplete coordinates, invalid radii, work offsets and some controller modes remain unresolved or explicitly limited.
4. **Feature recognition:** `engine/recognition.py` finds small-loop, large-closed-path, raster/zigzag, elongated and unclassified candidates; it groups similar loops, detects mirrored layouts and geometrically coincident paths at different depths. These labels are not claims that a path is a hole, pocket, finished contour or any other physical operation.
5. **Parametric rules:** `engine/parametric.py` supports fixed, axis-stretch and rigid end-dependent preview rules. The operator must explicitly choose a rule for every detected feature; no feature silently defaults to fixed. It validates finite dimensions, reference ranges, feature IDs, closed paths, connectivity, and preserved arc radii. A transform that would distort an arc or fail to reach the requested envelope is rejected/reported. Large closed paths (door/window contours) support **segment-level stretch**: only axial straight moves bridging the reference band are lengthened, arcs and non-axial moves stay rigid (wholly below/above the band) or the transform fails closed; small loops and middle-scaling of closed paths remain prohibited.
6. **Visual editing and validation:** the authenticated `/cnc/engine/` workbench provides source loading, selectable feature cards/paths, separate operator interpretation labels, before/after overlay, zoom, shift-drag pan, cursor coordinates and two-point measurement. Geometry validation and source/line traceability are available; every result remains `safe_for_execution: false` and operator labels are returned only as an unpersisted review record.
7. **Controller/output gate:** `CncControllerProfile` stores manufacturer/model/firmware, adapter key, supported commands, exact tested source hashes and approval evidence; archived files can be bound to a profile. Engine candidates reach the machine only through the **verified workshop dialect bridge**: `engine/serializer.py` re-emits the source text as a *pure coordinate patch* (every non-changed line byte-identical, only X/Y — and, defensively, I/J — words of changed moves rewritten; incremental modes, G53 patches, R-format arcs, Z changes, semantics drift and inch sources are blocked) and `controller.postprocess_resize` then re-verifies the final text line-by-line against the exact workshop dialect (M141 preamble, I/J arcs, 1:1 header/body/post structure). Without that active adapter the preflight stays fail-closed exactly as before.

## Reassessment with the supplied target file

`reports/t.16.1090x450.2set.baseline.json` records the read-only baseline for the uploaded `t.16.1090x450.2set.cnc` (SHA-256 `375103b2377b21a1083baf57a6035b23b06d98df97255a715f50fe5890d8d7c5`). The raw CNC program is intentionally not copied into this repository. The report records 309 lines, 299 parsed moves, 11 motion blocks, 32 arcs, tool numbers 2/3, H3/H2, feed 10000/12000, spindle 16000/15000, unknown M141 and compact M6T3/M6T2. Units are not declared, G54 is present, G43/H is present, and the arc plane is not explicitly selected.

The new geometric analysis separates the two narrow longitudinal passes (approximately 17 by 1094 source units, at depths -7 and -14), the thin vertical edge-like path, two raster-like regions (X about 32.167–447.513, Y 223–867, median pitch 14 source units, at depths -7 and -14), four radius-2 small-loop candidates at depth -12, and a separate large closed path candidate (X 26.167–439.167, Y 2.542–1087.458, arcs at depths -14/-16). The loops are geometrically symmetric but are not asserted to be physical holes. G17 is assumed only for preview and lowers confidence. On this actual file, the legacy last-large-block heuristic selects block-0010 (the large closed path); its suspected raster-selection defect is still preserved by a separate synthetic regression fixture, not falsely reported as occurring in this target file.

**Stage 5 update:** rule modes include fixed features, piecewise linear stretch, rigid end dependency, and feature-to-feature dependency. Piecewise stretch fixes the start reference, maps the interval through the end reference to the expanded span, and translates later coordinates; the end reference itself moves (it is not a two-fixed-end middle-only stretch). Feature relations expose signed offset bases `min_to_min`, `max_to_max`, or `center_to_center`; omitted offsets retain the selected source offset. Dependency cycles, unknown/unresolved anchors, invalid offsets, arc distortion, disconnected geometry and unmet target dimensions are rejected/reported. This remains an explicit rule system, not a general CAD solver; it does not infer hole-center constraints or tool-clearance collision envelopes.

**Stage 6 update:** workbench profiles are persisted by exact parsed-source SHA-256 and authenticated owner; the source program itself is not stored in this profile table. UI supports save/load, operator interpretations, resolved-geometry anchors and a relative offset with an explicit basis. Manual source edits invalidate analysis, preview, and profile actions until re-analysis.

**Stage 7 started, not completed:** a preflight API now reports source/candidate geometry, changed move IDs, travel-limit checks, feed/spindle limit checks, unresolved work offsets/tool length, and blocking reasons. It always returns `allowed: false` and `output_generated: false`. There is no serializer or controller simulator. The supplied target cannot pass an output gate until its units, controller/firmware dialect (including M141 and compact tool-change forms), G54 origin, tool-length behavior, machine limits, and reference simulation/validation are established by qualified machine documentation and testing.

## Not yet approved for production

The actual controller/model/firmware and the requested source program have not been provided. No controller adapter is registered. Work offsets (G54–G59), tool-length compensation (G43), cutter compensation, canned cycles, subprograms/macros, probing, controller-specific M codes, and some arc formats are not fully modeled. Before enabling a postprocessor, provide the exact CNC source and controller documentation/profile, bind its source hash, add simulator/backplot and golden-file regressions for that controller, and have a qualified operator verify the result against the target machine. Until then, the system intentionally does not emit executable G-code.
