### بررسی دستی فایل‌های نامطمئن (طبق درخواست پرامپت)

* **t.7.2570x510.1set** — ۶ قطعهٔ قاب ۴۴۸×۴۲۱ (عمق کامل ۱۶/۱۴٫۵) + پنل‌های داخلی
  ۳۴۶×۲۸۵ که ≥۹۰٪ داخل قاب‌اند → طبق گام ۵ مشخصات «فرزند» شناخته می‌شوند (شمار
  مستقل قطعه نیستند) + ناحیه‌های جیبِ −۶٫۵/−۶/−۵ که کانتور را قطع می‌کنند →
  `orphan_loop`/عملیات، نه قطعه. جمع: ۶ قطعه + ۲۰ عملیات. (کشف قدیمیِ «۲۴ کانتور» =
  ۱۲ مسیر × ۲ پاس عمق؛ در مدل جدید ۱۲ حلقهٔ بیرونی → ۶ قطعهٔ دوپاسه.)
* **t.16.560x470.1set** — ۳ کانتور با bbox هم‌پوشان ولی **چندضلعی‌های جدا** (پین‌وِیل
  ۳پارهٔ درهم‌قفل). یعنی «اورلپ» واقعی مسیر نیست؛ درهم‌قفلی هندسی است → ۳ قطعهٔ
  گزارش‌شده با هشدار interlocking و **قفل خیر**؛ اما هر ویرایشی که آرایش نسبی را
  عوض کند در گیت برخوردِ ویرایش رد می‌شود (هم‌پوشانی bbox پیر را نمی‌توان بی‌صدا
  بزرگ کرد).
* **j.26.940x940.1set** — دقیقاً «۶ نوار + ۱ پاکت» = ۷ قطعه؛ نوارها درهم‌قفل‌اند
  (bbox هم‌پوشان، مسیر جدا) → قابل‌ویرایش با هشدار.
* **j.13m.380x280.6set** — کل فایل فقط یک شیار بستهٔ ۳۰۸×۲۱ با ۴ پاس عمق است

## ۳) منطق تشخیص (`engine/parts.py` — بدون Django، فقط stdlib)

۱. جداسازی حلقه‌ها: هر بلوک به **همهٔ** زیرحلقه‌های بسته شکسته می‌شود (نه فقط
   اولی — باگ ۶ کره) شامل دایرهٔ تک‌حرکتی؛ plungeهای فقط-Z هندسه نیستند.
۲. ادغام پاس‌های عمق: حلقه‌های با هندسهٔ XY یکسان تا ۰٫۶mm → یک «مسیر چندپاسه»
   با فهرست عمق‌ها (Z−۱۴ و Z−۱۶ یک قطعه‌اند).
۳. کاندیدای کانتور بیرونی: عمق نهایی ≥ ۸۰٪ ضخامت ورق (بیشترین عمق منفی فایل یا
   پارامتر اپراتور) **و** محصور نبودن در هیچ حلقهٔ دیگر (پنجرهٔ تمام‌عمق = فرزند،
   نه قطعه) **و** عبورنکردن مسیر دیگر از آن. آستانهٔ ۱۰۰mm حذف شد؛ حداقل اندازه
   ۱۵mm قابل‌تنظیم (`min_part_size`).
۴. درخت شمول با آزمون نقطه‌در‌چندضلعی (نه bbox): سوراخ/پاکت/حکاکی → فرزند
   کوچک‌ترین کانتور شامل‌شونده؛ حلقهٔ بیرون از همه → عملیات مستقل.
۵. مسیرهای باز: `raster` / `saw_line` / `groove` / `engraving`؛ نزدیک‌ترین قطعه
   به‌عنوان میزبان، وگرنه عملیات مستقل.
۶. هم‌پوشانی خطرناک: تقاطع/نفوذ دوطرفهٔ دو کانتور → هر دو قطعه اما `locked=true`
   (ویرایش ممنوع). bbox هم‌پوشان با چندضلعی جدا = درهم‌قفلی مشروع → فقط هشدار.
۷. طبقه‌بندی شکل: `rect` / `rect_rounded` / `tapered` / `circle` / `freeform` با
   قابلیت‌های صریح: `can_translate` همیشه، `can_stretch_y/x` فقط وقتی نوار خطوط
   صاف موازی محور وجود دارد (قوس‌ها و مورب‌ها بیرون نوار)، `can_rotate90` /
   `can_mirror` برای کانتور بسته. قطعهٔ گرد/مایل خطا نمی‌دهد — فقط محدودتر است.
۸. خروجی ساختاریافته: `id` پایدار (hash هندسه، نه ترتیب بلوک؛ دوقلوها پسوند
   `#k`)، `passes[{z, block_id, source_lines}]`، `bbox` (مسیر ابزار) و
   `bbox_finished` (با جبران قطر ابزار از میز ابزار)، `children`، `shape_kind`،
   `capabilities`، `tool`، `warnings`.
۹. تطبیق نام فایل (اختیاری، فقط هشدار): الگوی `WxH` و `Nset`.
۱۰. **بدون Django اجرا می‌شود**: `python -m unittest cnc_resizer.engine.test_parts`

## ۴) API (فاز ۱)

`POST /cnc/api/parts/` با `{content, filename?, params?}` →
`{ok, parts, operations, sheet_bbox, sheet_bbox_finished, warnings, ...}` —
فقط‌خواندنی، با `cnc_operator_required`، `tool_map` همیشه از میز ابزار دیتابیس
تزریق می‌شود و کلاینت آن را نمی‌فرستد. هیچ متنی از این مسیر برنمی‌گردد.

## ۵) ویرایش قطعه‌محور (فاز ۲)

`engine/part_edits.py` ویرایش‌ها را به تبدیل‌های بلوکیِ همان ماشین‌آلات تست‌شده
پایین می‌کشد (lowering):

* `move_part {part_id, dx, dy}` — همهٔ بلوک‌های قطعه (همهٔ پاس‌ها + فرزندان +
  عملیات میزبان) با یک دلتا → همان `_shift_block_rigid` سطح ویژگی.
* `stretch_part {part_id, axis, delta|new_size, band?}` — فقط داخل نوار خطوط
  صاف؛ قوس‌ها هرگز آفست متفاوت نمی‌گیرند؛ ورودِ جابه‌جاشده روی rapid خود بلوک
  وصله می‌شود (همان قرارداد `_stretch_feature_x`)؛ فرزندِ روی نوار = رد؛ بقیهٔ
  ورق بالای نوار صلب جابه‌جا می‌شود؛ **انتخاب قطعه با کاربر است، الگوریتم حدس
  نمی‌زند**.
* `set_gap {part_a, part_b, gap, axis}` و `distribute {axis, parts, gap}` — از
  روی `bbox_finished` (شامل قطر ابزار).
* راستی‌آزمایی: serialize (وصلهٔ مختصاتی خالص) → reparse زمان اجرا → شمارش ۱:۱
  حرکت/بلوک، Z دست‌نخورده، bbox هر بلوک ویرایش‌شده = انتظار، بلوک‌های دست‌نخورده
  بایت‌پایدار → گیت برخورد در سطح bbox نهایی قطعه‌ها: هم‌پوشانی جزئیِ **تازه** رد؛
  هم‌پوشانی از پیش موجود فقط وقتی مجاز که هیچ محوری بدتر نشود یا آرایش حفظ شود؛
  تودرتویی مجاز.
* خروجی نهایی همچنان فقط از `serializer.py` + `controller.postprocess_resize`
  (دروازهٔ دیالکت) — از `api/engine/output/` بدون هیچ مسیر موازی.

مسیریابی: همان `edits` موجود در `api/engine/preview/` و `api/engine/output/`
است؛ اگر همهٔ آیتم‌ها `part_id`/`part_a`/`parts` داشته باشند به موتور قطعه می‌روند
(نام مشترک `set_gap` بین دو واژگان با فیلد مرجع تفکیک می‌شود).
