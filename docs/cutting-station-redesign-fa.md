# مستند طراحی «ایستگاه برش CraftFlow» — بازطراحی عمیق ماژول برش و CNC

مرجع استاندارد: سه اسکرین‌شات ارائه‌شده توسط کاربر — AutoCUT 开料专家 (بهینه‌ساز)، AutoCUT+AutoSAW Simulation (چیدمان و شبیه‌سازی)، AutoSAW System (اجرا و مانیتور).

سطح این نسخه: **A** — بازطراحی کامل لایهٔ ارائه (قالب‌ها، CSS، JS) بدون تغییر مدل داده، بدون تغییر الگوریتم چیدمان و بدون تغییر خروجی‌ها.

## ۲. معماری ارائه — «ایستگاه» تک‌پوسته‌ای

همهٔ صفحات برش/CNC یک پوستهٔ مشترک `.station` می‌گیرند (تم تیرهٔ صنعتی مثل AutoSAW، بوم روشن در مرکز):

```
┌──────────────────────────────────────────────────────────┐
│ نوار بالای ایستگاه (cutting-nav بازطراحی): حالت‌ها + هویت │
├────────────┬──────────────────────────────┬──────────────┤
│ Worklist / │ بوم بزرگ چیدمان (SVG روشن    │ پنل جزئیات/  │
│ لیست ورق‌ها │ روی زمینهٔ تیره + شبکه)      │ ثبت نتیجه    │
├────────────┴──────────────────────────────┴──────────────┤
│ نوار وضعیت: پارامترها · برش جاری · مختصات · پرت مانده    │
└──────────────────────────────────────────────────────────┘
```

نگاشت حالت‌ها روی URLهای فعلی (هیچ URL عوض نمی‌شود):

| حالت | URL فعلی | قالب |
|------|----------|------|
| داده (Data) | `cutting:planner` | planner.html — صف سفارش‌ها به‌جای Worklist، پنل تأمین/نیاز، نوار پارامتر |
| چیدمان + اجرا + شبیه‌سازی (Layout/Process/Simulate) | `cutting:plan_detail` | plan_detail.html — تب حالت داخل صفحه، بوم بزرگ، ثبت نتیجه |
| گزارش (Record) | `cutting:plans` و `cutting:history` | plan_list.html / history.html — فهرست‌های تیره |
| CNC | `cnc_resizer:sheet_plans` | sheet_plans.html — چیدمان استاد-جزئیات |
| انبار/تنظیمات | inventory، size_specs، policy، stock_form | پوستهٔ تیره با کمترین تغییر مارک‌آپ |

## ۴. اجزای جدید

1. **station head** — عنوان حالت + چیپ‌های KPI (ورق/قطعه/بهره‌وری/پرت).
2. **mode-tabs** — تب‌های «چیدمان / اجرا / شبیه‌سازی» در plan_detail (کلاینت‌ساید، روی `data-mode` ریشهٔ ایستگاه).
3. **بوم بزرگ** — همان SVG `cut-map` با قاب تیره، شبکهٔ زمینه، برچسب گوشه (ابعاد ورق)، ارتفاع تا `calc(100vh - …)`.
4. **نوار وضعیت** (پایین، sticky) — در plan_detail: تیغه، سیاست، پیشرفت ثبت، برش جاری شبیه‌سازی؛ در planner: انتخاب‌ها + تیغه + دکمهٔ محاسبه (جای cutting-sticky-bar قبلی).
5. **شبیه‌سازی برش (cut_sim.js)** — ترتیب برش قفسه‌ای:
   - ورودی: `<script type="application/json" data-cut-sim>` داخل هر sheet-panel با `{w,h,kerf,parts:[{no,x,y,width,height,rotated}]}`.
   - الگوریتم قطعی: گروه‌بندی قطعات بر اساس `y` (طبقه‌ها)، مرتب‌سازی طبقه‌ها بالا→پایین و قطعات داخل طبقه راست‌→چپ (RTL نمایشی؛ مختصات فیزیکی LTR حفظ می‌شود)؛ برای هر طبقه: برش طولی لبهٔ طبقه، سپس برش‌های عرضی میان قطعات؛ برش سربرِ ابتدای ورق و پاک‌تراش انتهایی.
   - خروجی نمایشی: شمارهٔ برش، نوع (طولی/عرضی)، مختصات X/Y، قطعهٔ جدا‌شده؛ پخش انیمیشن خط برش روی لایهٔ overlay با پخش/توقف/گام/سرعت؛ فهرست «ماندهٔ ورق» به‌روز می‌شود.
   - این ترتیب «فرضی برای پیش‌نمایش» است و در فایل .CUT/CNC دخالتی ندارد (فاز B ترتیب واقعی Guillotine را تولید می‌کند).
6. **sheet_plans استاد-جزئیات** — فهرست فشردهٔ برنامه‌ها + بوم بزرگ برنامهٔ انتخابی + پنل «نیازمند بررسی»؛ همهٔ فرم‌ها و هوک‌ها (`data-cnc-result`، دانلود، لغو، رفع issue) حفظ می‌شوند.

## ۵. سازگاری و قیود سخت

- URLها، نام‌ها و ساختار فرم‌ها ثابت: `order_ids`، `kerf`، `stock_policy`، `planning_mode`، `outcome_{{pk}}`، `note_{{pk}}`، `rem_{{pk}}_n_width/height`، `name="default_kerf"`، …
- هوک‌های JS ثابت: `planning-form`، `order-rows`، `preview-*`، `plan-submit`، `data-sheet-panel`، `sheet-tab`، `data-material-tab/section/progress`، `outcome-group`، `remnants-*`، `sheet-progress-*`، `mark-all-used`، `open-confirm`، `cut-download-trigger`، `data-cnc-result`، …
- رشته‌های تحت پوشش تست که نباید حذف شوند: «انتخاب نمایان‌ها»، «پیش‌نمایش نیاز مواد»، «نتیجه واقعی این ورق»، «همه مصرف شدند»، «پذیرش این فایل روی کنترلر دستگاه تأیید نشده»، «این برنامه لغو شده و رزروها آزاد شدند»، «ثبت نتیجهٔ اجرا»، «نادیده‌گرفتن»، «فایل دستگاه تأیید نشده»، «دریافت فایل دستگاه»، «خروجی ورق CNC»، «CUT و CNC»، «رزرو شده؛ قفل»، «زمان شمسی»، «ثبت سریع چند پرت پشت‌سرهم»، `class="cutting-nav`، `class="cutting-stepper`، `class="cut-map"`، `data-material-tab="1"`، `>1</text>`، `placeholder="اندازه‌گیری شود"`.
- عبارت «فایل دستگاه تولید نشده» نباید در sheet_plans ظاهر شود (تست assertNotContains).
- خروجی `make_autocut`، خط لولهٔ `cnc_resizer` (adapter/G-code) و مدل‌ها دست‌نخورده.
- چاپ برگهٔ اپراتور: در چاپ، ایستگاه به زمینهٔ روشن برمی‌گردد و فقط سربرگ/بوم/فهرست قطعات چاپ می‌شود.

## ۶. فاز B (پس از تأیید این فاز)

- موتور چندالگوریتمی (قفسه‌ای فعلی + Guillotine/Skyline)، رگه، سربر مستقل، مقایسهٔ بهره‌وری و انتخاب بهترین، ترتیب برش واقعی برای شبیه‌سازی و خروجی.
- یکسان‌سازی کامل دو ابزار متخصص CNC (index، engine_workbench) با پوستهٔ ایستگاه.
- نمودارهای Record/Chart (بهره‌وری در زمان، پرت به‌تفکیک متریال).

## ۷. معیار پذیرش فاز A

- همهٔ صفحات برش/CNC یک هویت تیرهٔ ایستگاهی دارند؛ بوم چیدمان در plan_detail بزرگ‌تر و کانونی است.
- شبیه‌سازی ترتیب برش روی هر ورق قابل پخش است و مختصات/شمارهٔ برش/مانده را نشان می‌دهد.
- کل تست‌های موجود (cutting + cnc_resizer) بدون تغییر معنایی پاس شوند؛ دودآزمایی رندر همهٔ صفحات 200.
- موبایل: پنل‌ها پشته می‌شوند؛ بوم و نوار وضعیت قابل استفاده می‌مانند.
