# راهنمای تست تغییرات جدید CraftFlow در محیط لوکال

این راهنما برای بررسی تغییرات شاخهٔ زیر نوشته شده است:

```text
feature/cnc-archive-index
```

تغییرات این شاخه شامل بهبود گردش کار برش، رابط کاربری انبار، برنامه‌ریزی `.CUT`، تفکیک CNC، ثبت خطاهای قطعات و بهبود صفحهٔ جزئیات برنامهٔ برش است.

## ۱. دریافت آخرین نسخهٔ شاخه

اگر مخزن را قبلاً clone کرده‌اید:

```bash
git fetch origin
git switch feature/cnc-archive-index
git pull --ff-only origin feature/cnc-archive-index
```

اگر شاخه روی سیستم شما وجود ندارد:

```bash
git fetch origin
git switch --track origin/feature/cnc-archive-index
```

بررسی کنید روی commit جدید هستید:

```bash
git status --short --branch
git log -1 --oneline
```

Commit مربوط به آخرین فاز رابط کاربری:

```text
ff7b62a Complete cutting workflow UX improvements
```

## ۲. ساخت یا فعال‌کردن محیط مجازی

در ریشهٔ پروژه، یعنی محلی که `manage.py` قرار دارد، اجرا کنید.

### Linux و macOS

```bash
python3 -m venv .venv
source .venv/bin/activate
```

### Windows PowerShell

```powershell
py -m venv .venv
.venv\Scripts\Activate.ps1
```

سپس وابستگی‌ها را نصب کنید:

```bash
python -m pip install --upgrade pip
pip install -r requirements.txt
```

## ۳. تنظیم متغیرهای محیطی

برای تست محلی حداقل این مقادیر لازم است.

### Linux و macOS

```bash
export SECRET_KEY='local-development-key'
export DEBUG='True'
export ALLOWED_HOSTS='127.0.0.1,localhost'
```

### Windows PowerShell

```powershell
$env:SECRET_KEY = 'local-development-key'
$env:DEBUG = 'True'
$env:ALLOWED_HOSTS = '127.0.0.1,localhost'
```

اگر پروژه از فایل `.env` استفاده می‌کند، همین مقادیر را در فایل محلی خود قرار دهید و فایل `.env` را commit نکنید.

## ۴. اعمال migrationها

قبل از اجرای برنامه، migrationهای جدید را اعمال کنید:

```bash
python manage.py migrate
```

برای بررسی migrationهای اجراشده:

```bash
python manage.py showmigrations cnc_resizer cutting
```

Migration مربوط به ثبت خطاهای برنامه‌ریزی CNC باید اجرا شده باشد:

```text
cnc_resizer.0004_cncplanningissue
```

برای بررسی سلامت تنظیمات Django:

```bash
python manage.py check
```

## ۵. اجرای تست خودکار

ابتدا تست‌های اصلی بخش برش و CNC را اجرا کنید:

```bash
python manage.py test cutting cnc_resizer --verbosity 1
```

اجرای کامل تست‌های پروژه:

```bash
python manage.py test --verbosity 1
```

نتیجهٔ مورد انتظار برای تست‌های مربوط به این تغییرات:

```text
49 tests ... OK
```

عدد تست‌ها ممکن است با تغییرات بعدی پروژه بیشتر شود؛ مهم این است که خروجی با `OK` پایان یابد و تستی fail نشود.

برای بررسی خطاهای فرمت و syntax فایل‌های Python:

```bash
python -m compileall -q cutting cnc_resizer
```

برای بررسی فاصله‌های نامعتبر در تغییرات Git:

```bash
git diff --check
```

## ۶. اجرای سرور محلی

```bash
python manage.py runserver 127.0.0.1:8000
```

سپس در مرورگر باز کنید:

```text
http://127.0.0.1:8000/cutting/
```

برای توقف سرور:

```text
Ctrl+C
```

اگر کاربر مدیر ندارید، یک کاربر بسازید:

```bash
python manage.py createsuperuser
```

دسترسی‌های بخش برش ممکن است به گروه‌ها و سطح دسترسی پروژه وابسته باشد. اگر کاربر واردشده صفحه را با خطای دسترسی می‌بیند، از کاربری استفاده کنید که مجوز اپراتور برش یا انبار را دارد.

## ۷. چک‌لیست بررسی صفحهٔ برنامه‌ریزی برش

به آدرس زیر بروید:

```text
/cutting/
```

این موارد را بررسی کنید:

- سفارش‌های دارای تسک برش در جدول نمایش داده شوند.
- جست‌وجوی شماره سفارش و نام مشتری کار کند.
- فیلتر وضعیت سفارش نتیجهٔ درست بدهد.
- با انتخاب ردیف سفارش، ردیف از نظر بصری مشخص شود.
- تعداد سفارش‌ها و قطعات انتخاب‌شده در پیش‌نمایش تغییر کند.
- پیش‌نمایش مواد، ورق آزاد، رزرو و کسری نمایش داده شود.
- تغییر ضخامت تیغه، پیش‌نمایش را به‌روزرسانی کند.
- حالت «روش فعلی؛ تولید فایل `.CUT`» قابل انتخاب باشد.
- حالت «تفکیک CNC؛ ساخت G-code برای هر ورق» قابل انتخاب باشد.
- توضیح محورهای مختصات به‌درستی نمایش داده شود:

  ```text
  CUT:  X = Part.length ، Y = Part.width
  CNC:  Y = Part.length
  ```

- دکمهٔ «محاسبه و رزرو» فقط پس از انتخاب سفارش فعال شود.
- روی صفحهٔ کوچک یا موبایل، نوار اقدام اصلی مزاحم فرم نباشد.

## ۸. تست برنامه‌ریزی فایل CUT

1. یک سفارش دارای تسک برش انتخاب کنید.
2. حالت استاندارد را انتخاب کنید.
3. روی «محاسبه و رزرو» کلیک کنید.
4. وارد صفحهٔ جزئیات برنامه شوید.
5. بررسی کنید:
   - تعداد ورق‌ها و قطعات درست است.
   - نقشهٔ چیدمان نمایش داده می‌شود.
   - ابعاد قطعات در نقشه خوانا است.
   - طول قطعه در فایل CUT روی محور `X` و عرض روی محور `Y` قرار دارد.
   - دانلود فایل `.CUT` کار می‌کند.

## ۹. تست صفحهٔ جزئیات برنامه

در صفحهٔ جزئیات برنامه، معمولاً آدرس به شکل زیر است:

```text
/cutting/plans/<PLAN_ID>/
```

موارد زیر را بررسی کنید:

- نوار پیشرفت ثبت نتیجهٔ ورق‌ها نمایش داده شود.
- تعداد ورق‌های ثبت‌شده و باقی‌مانده درست باشد.
- وضعیت هر ورق در تب آن مشخص باشد:
  - ثبت‌نشده
  - مصرف‌شده
  - دست‌نخورده
  - اسقاط‌شده
- انتخاب یک نتیجه، رنگ تب و نوار پیشرفت را فوراً تغییر دهد.
- دکمهٔ «همه ورق‌ها مصرف شدند» همهٔ ورق‌ها را انتخاب کند.
- ثبت ورق اسقاط‌شده بدون یادداشت امکان‌پذیر نباشد.
- ثبت پرت واقعی با عرض و طول معتبر انجام شود.
- واردکردن عدد بیشتر از ابعاد ورق خطا بدهد.
- «مرور و تأیید نتیجه» قبل از ثبت، خلاصهٔ عملیات را نشان دهد.
- پس از ثبت نهایی، فقط ورق‌های مصرف‌شده از موجودی کسر شوند.
- ورق دست‌نخورده به موجودی برگردد و ورق اسقاط‌شده به‌عنوان اسقاط ثبت شود.

برای تست بدون تغییر واقعی موجودی، ابتدا روی یک دیتابیس توسعه یا backup جداگانه کار کنید.

## ۱۰. تست صفحهٔ انبار ورق

آدرس:

```text
/cutting/inventory/
```

بررسی کنید:

- کارت‌های موجودی کل، رزروشده و آزاد نمایش داده شوند.
- عبارت «آزاد = کل منهای رزرو» قابل فهم باشد.
- فیلترهای سریع «همه»، «ورق کامل» و «پرت قابل استفاده» کار کنند.
- جست‌وجوی متریال و ابعاد کار کند.
- فیلتر متریال، ضخامت و مرتب‌سازی نتیجه را تغییر دهد.
- ورق کامل و پرت از نظر متن و رنگ قابل تشخیص باشند.
- مقدار «آزاد / کل» و مقدار رزرو به‌درستی نمایش داده شود.
- ویرایش موجودی به علت اصلاح نیاز داشته باشد، اگر مقدار حساس تغییر کند.
- غیرفعال‌سازی موجودی بدون علت انجام نشود.
- موجودی رزروشده قابل غیرفعال‌سازی نباشد.

## ۱۱. تست ثبت موجودی

آدرس:

```text
/cutting/inventory/stock/create/
```

موارد زیر را بررسی کنید:

- انتخاب «ورق کامل» و «پرت قابل استفاده» واضح باشد.
- برای ورق کامل، اندازهٔ استاندارد پیش‌فرض متریال انتخاب شود.
- با تغییر متریال، اندازهٔ استاندارد متریال قبلی باقی نماند.
- برای پرت، حالت اندازهٔ سفارشی فعال شود.
- ابعاد با قرارداد زیر ثبت شوند:

  ```text
  عرض × طول
  ```

- تعداد ورق‌های مشابه به‌صورت گروهی ثبت شود.
- گزینهٔ ثبت سریع پرت، فرم بعدی را با اطلاعات مناسب باز کند.
- مقدار اولویت و جهت رگه ذخیره شود.

## ۱۲. تست فهرست برنامه‌ها و تاریخچه

### فهرست برنامه‌ها

```text
/cutting/plans/
```

بررسی کنید:

- فیلتر سریع همه، برنامه‌ریزی‌شده، انجام‌شده، جزئی و لغوشده کار کند.
- جست‌وجوی شماره برنامه، سفارش و مشتری کار کند.
- تعداد ورق و قطعه درست باشد.
- وضعیت برنامه فقط با رنگ نمایش داده نشود و متن وضعیت نیز وجود داشته باشد.

### تاریخچهٔ موجودی

```text
/cutting/history/
```

بررسی کنید:

- فیلتر سریع مصرف، پرت، ورود و اسقاط کار کند.
- فیلتر متریال و نوع رویداد کار کند.
- تاریخ شمسی با قالب `YYYY/MM/DD` پذیرفته شود.
- تاریخ میلادی `YYYY-MM-DD` نیز در صورت پشتیبانی محیط پذیرفته شود.
- تاریخ شروع بعد از تاریخ پایان پیام خطا بدهد.
- لینک برنامه از رویدادهای مربوط به برنامه باز شود.

## ۱۳. تست تفکیک CNC

1. یک سفارش دارای قطعات CNC-first انتخاب کنید.
2. حالت زیر را انتخاب کنید:

   ```text
   تفکیک CNC؛ ساخت G-code برای هر ورق
   ```

3. برنامه را ایجاد کنید.
4. به صفحهٔ خروجی ورق CNC بروید:

   ```text
   /cnc/sheets/
   ```

5. بررسی کنید:
   - برای هر ورق فایل G-code جدا ساخته شود.
   - قطعات CNC-first در فایل `.CUT` تکرار نشوند.
   - طول CNC روی محور `Y` باقی بماند.
   - قطعات هم‌متریال در یک برنامهٔ ورق کنار هم قرار گیرند.
   - فایل G-code قابل دانلود باشد.

## ۱۴. تست قطعهٔ مشکل‌دار

برای بررسی رفتار مقاوم در برابر خطا، یکی از این شرایط را در دیتابیس توسعه ایجاد کنید:

- قطعه بدون فایل پایهٔ CNC
- قطعه‌ای که فایل پایهٔ آن قابل resize نیست ولی ابعادش با پایه برابر است
- قطعه‌ای با ابعاد بزرگ‌تر از همهٔ ورق‌های موجود
- قطعه‌ای با ابعاد صفر یا منفی در دادهٔ آزمایشی
- متریالی بدون ورق آزاد

سپس برنامه‌ریزی را اجرا کنید و بررسی کنید:

- برنامه به‌طور کامل با خطای ۵۰۰ متوقف نشود.
- قطعات سالم در برنامه باقی بمانند.
- قطعهٔ مشکل‌دار از چیدمان همان اجرا کنار گذاشته شود.
- خطا در بخش «خطاهای قطعات عبور داده‌شده» ثبت شود.
- شمارهٔ تسک، سفارش، قطعه و علت خطا قابل مشاهده باشد.
- قطعهٔ خطادار به‌صورت خودکار انجام‌شده نشود.

## ۱۵. تست واکنش‌گرایی و دسترس‌پذیری

در DevTools مرورگر، عرض‌های زیر را بررسی کنید:

- ۳۷۵ پیکسل: موبایل
- ۷۶۸ پیکسل: تبلت
- ۱۲۸۰ پیکسل: دسکتاپ

موارد بررسی:

- جدول‌ها امکان اسکرول افقی داشته باشند و اطلاعات اصلی حذف نشود.
- دکمهٔ اصلی خارج از صفحه نرود.
- نوار ثابت پایین صفحه روی دکمه‌ها و فیلدها قرار نگیرد.
- تب ورق‌ها قابل استفاده با لمس باشند.
- ترتیب Tab منطقی باشد.
- عنصر فعال با `aria-current` و وضعیت‌های مهم با متن، نه فقط رنگ، مشخص شوند.

## ۱۶. پاک‌سازی پس از تست

اگر روی دیتابیس آزمایشی کار می‌کنید، برنامه‌های ایجادشده را از طریق رابط کاربری لغو کنید تا رزرو ورق‌ها آزاد شود. برای تست‌های حساس از دیتابیس جداگانه استفاده کنید و هیچ‌گاه دیتابیس تولید را برای تست UI تغییر ندهید.

در پایان وضعیت Git را بررسی کنید:

```bash
git status --short
```

اگر فقط قصد بررسی دارید، هیچ فایل تغییریافته‌ای نباید باقی مانده باشد.

## ۱۷. گزارش خطا

برای گزارش یک مشکل، این اطلاعات را ثبت کنید:

- شاخه و commit فعلی:

  ```bash
  git branch --show-current
  git log -1 --oneline
  ```

- مسیر صفحه
- نقش کاربر
- شماره سفارش، برنامه یا تسک
- مراحل دقیق بازتولید
- نتیجهٔ مورد انتظار
- نتیجهٔ واقعی
- تصویر یا متن خطا
- اندازهٔ صفحه و مرورگر
- خروجی دستور زیر:

  ```bash
  python manage.py check
  ```

از ارسال `SECRET_KEY`، رمز عبور، توکن یا اطلاعات حساس مشتری در گزارش خودداری کنید.
